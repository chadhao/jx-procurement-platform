## 2. 参与者定义

| 参与者 | 类型 | 说明 |
|---|---|---|
| 申请人 | 人 | 各部门全员；可提需求、可参与验收（仅查看） |
| 主管领导 | 人 | 综合运营部 / 质检技术部 → 项目总经理；生产部 / 销售部 → 副总；**在该环节指定采购经办人** |
| 项目总经理 | 人 | 第二级审批人 / 终审 |
| 副总 | 人 | 生产部、销售部的第一级审批人 |
| 综合运营主管 | 人 | 归口核心；唯一对接集团的人；采一档备付金审批 |
| 采购经办人 | 人 | 审批时指定；询比价、组织合同、下单跟单 |
| 验收人 | 人 | 按品类三组（设备耗材类 / 原辅料类 / 其他类） |
| 质检技术部 | 部门角色 | 验收三组构成之一；发起「来料检验报告（QC）」 |
| 库管 | 部门角色 | 仅原辅料类（P01）验收三方构成之一 |
| 系统管理员 | 人 | 配置与权限维护，**不参与业务审批** |
| 飞书审批引擎 | 外部系统 | 审批流转发生地；推送 `approval_instance` / `approval_task` 事件 |
| 自建系统 | 系统 | 本系统；**只收不转** |
| 集团财务 | 外部人工 | 集团侧付款执行；**不回传数据** |

## 4. 用例详述

### UC-01　飞书免登与身份识别

| 项 | 内容 |
|---|---|
| **参与者** | 全角色（主）、自建系统 |
| **前置条件** | 飞书自建应用已创建并申请「通讯录读取（免登用）」权限；用户为飞书组织成员 |
| **主流程** | 1. 用户访问自建系统受保护页面。<br>2. 系统检测到无有效会话 → 跳转飞书免登授权。<br>3. 用户完成授权，回调 `GET /auth/feishu/callback`。<br>4. 系统用授权码换取用户身份，得到 `open_id`。<br>5. 系统按 `t_user_role` 查 `open_id → 角色`。<br>6. 系统建立会话，按角色加载可见行范围与可见列集合。<br>7. 用户进入页面。 |
| **异常流 / 备选流** | A1. 回调失败 / 授权被拒 → 提示失败，回到未登录态，不建立会话。<br>A2. `open_id` 未映射到任何角色 → **拒绝进入业务页面**（默认无权限），仅显示提示；由系统管理员补配角色。<br>A3. 用户在飞书被调岗 / 角色变更 → 下次请求时重新解析角色，权限**即时生效**。 |
| **后置条件** | 会话建立；系统已知「你是谁」；行 / 列权限可按角色生效 |
| **关联需求** | FR-M0-10、FR-M5-04 |

> ★ 行·列权限的前提是「知道你是谁」——飞书免登是本系统分权能力的前置。

### UC-02　采购报备与备付金签领（采一档 <1,000 元）

| 项 | 内容 |
|---|---|
| **参与者** | 申请人（主）、综合运营主管、飞书审批引擎、自建系统 |
| **前置条件** | 采购报备单模板已建好并订阅；备付金实有金额已知（不设定额） |
| **主流程** | 1. 申请人在**飞书审批**内提交采购报备单（填分类、二级明细、数量、金额、供应商、事由、到货日期）。<br>2. 飞书推送 `approval_instance` 事件；自建系统写「待处理」记录后立即返回。<br>3. 自建系统异步拉取实例详情，落库并归档单号（`BA-YYMM-####`）。<br>4. 综合运营主管在飞书内审批「备付金是否充足」（只判付款能力，不判需求必要性）。<br>5. 校验防拆分与次数上限（**不通过即转档或退回，须在拨付款项之前完成**）：系统以台账红标提示（同供应商 + 同二级明细当月累计 ≥1,000 元即预警并强制转采二档）。<br>6. 综合运营主管拨付备付金，**申请人在备案单上签领**（签领人 / 金额 / 日期）。<br>7. 自建系统登记**备付金签领记录**（FR-M1-01）。<br>8. **申请人自购**（谁申请谁购买；本档明文豁免「禁止自我经办」）。<br>9. 申请人回交付款凭据；自建系统补录审批人、付款凭据号（FR-M1-03）。<br>10. 到货后由申请部门或仓储完成到货登记与入库。<br>11. 综合运营主管按月凭单据向集团核销补足，登记核销后余额；台账与月度报送引用。 |
| **异常流 / 备选流** | A1. 备付金不足 → 综合运营主管在**三项处置中择一**：① 现场向集团申请备付金　② 延后申请、延后执行　③ 拒绝审批；三项处置须在单据上留痕。<br>A2. 拆分 / 次数校验不通过 → 转采二档或退回，不拨付。<br>A3. 综合运营主管本人需求（即使 <1,000 元）→ **审批上抬至主管领导**，本人不得自审自购，台账单独标记。<br>A4. 综合运营主管不在岗 → **备付金审批不得代理**；采一档顺延或改走延后执行；确需即时的走紧急采购通道。 |
| **后置条件** | 签领记录、付款凭据与备案单逐笔一一对应；核销后余额可查 |
| **关联需求** | FR-M1-01、FR-M1-03、FR-M1-05、FR-M1-07、FR-M2-04、FR-M4-04、FR-M4-05 |

> ★ 本档是**三道门槛（签不签合同 / 走不走公户 / 走不走合同两级审批）的唯一豁免档**，故防拆分规则是本档能否成立的前提（制度第十八条、第二十一条）。

### UC-03　物资采购申请（采二档 1,000–5,000 元，含指定经办人）

| 项 | 内容 |
|---|---|
| **参与者** | 申请人（主）、主管领导、采购经办人、飞书审批引擎、自建系统 |
| **前置条件** | 物资采购申请单模板已建好并订阅，审批节点已配置「指定采购经办人」必填字段与「指定人与指定时间」系统带入字段 |
| **主流程** | 1. 申请人在飞书内提交物资采购申请单（填需求类型、用途说明、需求日期、紧急程度、预算科目、明细行；预估总金额为计算列，禁止手填）。<br>2. 飞书推送事件；自建系统写「待处理」记录后立即返回，异步落库并归档单号（`PR-YYMM-####`）。<br>3. 主管领导审批「要不要买」，并**在该审批节点当场指定采购经办人**（必填；**不得指定需求提出人本人**；跨部门指定须经被指定部门主管领导同意）。<br>4. 系统带入「指定人（即审批人）」与「指定时间」，写入采购经办登记台账（同步存档表）。<br>5. 采购经办人取得报价依据（≥1 家报价或框架协议价 / 历史成交价）。<br>6. 转入合同流程（见 UC-07）；确不签合同的须在采购申请单中说明理由，由主管领导审批时一并确认并计入月度抽查。<br>7. 到货验收（见 UC-11）。<br>8. 报综合运营主管初审（含「经办人 ≠ 需求提出人」身份核对）。<br>9. 提交集团公户付款（见 UC-12）。 |
| **异常流 / 备选流** | A1. 主管领导在审批节点**未填经办人** → 因该字段为必填，飞书侧不允许提交（流程阻塞在飞书，不在本系统）。<br>A2. 核出「经办人 = 需求提出人」→ **本单不退回、已执行的操作不撤回**；按制度第五十八条移交人事管理制度考核，同时计入监督指标「需求提出人任经办人的笔数」（FR-M5-07）。<br>A3. 报价依据缺失 → 计入月度抽查异常。 |
| **后置条件** | 「谁审的、审的时候指定了谁、谁办的」三者可追溯 |
| **关联需求** | FR-M2-01、FR-M2-02、FR-M2-06、FR-M3-01、FR-M4-03、FR-M4-04、FR-M5-07 |

> ★ 「指定经办人 ≠ 需求提出人」**不可在系统层做跨字段校验**（飞书原生审批不支持），只能事后核对（制度第十三条、第十四条、第六十条）。

### UC-04　物资采购申请（采三档 >5,000 元，询比价 ≥3 家）

| 项 | 内容 |
|---|---|
| **参与者** | 申请人（主）、主管领导、项目总经理、采购经办人、飞书审批引擎、自建系统 |
| **前置条件** | 同 UC-03；询价单 / 比价表模板已建好 |
| **主流程** | 1. 申请人在飞书内提交物资采购申请单。<br>2. 事件落库并归档（`PR-YYMM-####`）。<br>3. 主管领导审批（要不要买 + 指定经办人）。<br>4. 采购经办人组织询比价（**≥3 家独立报价**，报价单位之间不得存在关联关系），编制询价单与比价表（须含技术符合性评价栏）。<br>5. 主管领导审批 → 项目总经理审批（**确认拟成交单位**）。<br>6. 质检技术部技术评审（如需；P04 设备类单台/套 ≥20,000 元须附技术评审意见）。<br>7. 转入合同流程（见 UC-07）。<br>8. 到货验收（见 UC-11）。<br>9. 报综合运营主管初审（含经办人身份核对）→ 提交集团公户付款（见 UC-12）。 |
| **异常流 / 备选流** | A1. **主管领导即为项目总经理**（综合运营部 / 质检技术部事项）→ 审批链**随分管层级自然终止**，一级审批即终审，不另设第二级。<br>B1. 发现报价单位存在关联关系 → 该报价作废并重新询价。<br>B2. 仅以最低价定标 → 违规，计入月度抽查。<br>B3. 金额 >200,000 元或固定资产类 → 采购方式升级为招标 / 竞争性谈判。 |
| **后置条件** | 询比价材料齐备；拟成交单位经两级确认；可追溯 |
| **关联需求** | FR-M2-01、FR-M2-04、FR-M4-01、FR-M4-07 |

> ★ 采三档审批次数**保持不变**（批复 D4）：主管领导批 3 次、项目总经理批 2 次，保留「确认拟成交单位」的第二级。

### UC-05　费用事前申请（个人垫付线 · 销一档 / 管一档）

| 项 | 内容 |
|---|---|
| **参与者** | 申请人（主）、主管领导、综合运营主管、飞书审批引擎、自建系统 |
| **前置条件** | 费用事前申请单模板已建好；**销一档与管一档须配置为两条独立流程**（批复 C3 不合并） |
| **主流程** | 1. 申请人在费用发生**之前**提交费用事前申请单（填费用科目、用途分类 + 二级明细、事由、对象 / 接待对象、人数、预计金额、发生期间、支付方式）。<br>2. 事件落库并归档（`SA-YYMM-####`）。<br>3. 主管领导审批（**本流程唯一的事前审批节点，与金额无关**；审批要点：事由真实性、金额合理性、必要性、合规性）。<br>4. 获批后**申请人个人先行垫付**并执行事项（**垫付即为提前支出，无须等待集团流程**）。<br>5. 申请人整理票据并按**已批准的事前申请单号**关联（不设报销单）。<br>6. 综合运营主管初审四项：票据合规性与完整性、结算额 ≤ 申请额、分类正确、已关联申请单。<br>7. 自建系统登记「集团报销跟踪表」（人工登记）。<br>8. 综合运营主管归口移交集团（见 UC-12）。 |
| **异常流 / 备选流** | A1. **未取得已批准的事前申请单** → 一律不予受理，无例外审批通道；唯一例外是突发紧急事项：须事后 **24 小时内**补提交事由说明并取得主管领导确认，且单一部门月累计 ≤3 次。<br>A2. 结算额 > 申请额 → 须附书面说明并经主管领导确认，否则只按申请金额结算。<br>A3. 招待 / 烟酒类附件缺失（接待事由、对象单位与人数、参与人签字、含品名数量的消费明细）→ 初审不通过。<br>A4. 超期未移交票据（建议值 15 个工作日；超 30 天须说明、超 90 天须项目总经理批准）→ 计入异常。 |
| **后置条件** | 票据挂到已批准的事前申请单上；跟踪表登记完成 |
| **关联需求** | FR-M1-02、FR-M4-01、FR-M4-03 |

> ★ 招待与烟酒**不设单次限额、不设年度额度**（2026-09-25 批复）；管控由「审批链 + 必备附件 + 单列统计 + 后置审计 + 禁止性规定」承担。本系统**不得**实现金额门槛校验。

### UC-06　费用事前申请（对公直付线 · 管二档）

| 项 | 内容 |
|---|---|
| **参与者** | 申请人（主）、主管领导、综合运营主管、采购经办人（组织合同）、飞书审批引擎、自建系统 |
| **前置条件** | 同 UC-05；适用范围为房租物业、通讯网络软件订阅、审计评估认证、财务费用、能源动力（P08）等**无需个人垫付**事项 |
| **主流程** | 1. 申请人在费用发生前提交费用事前申请单（支付方式为「对公直付」）。<br>2. 事件落库并归档（`SA-YYMM-####`）。<br>3. 主管领导审批。<br>4. **交付物确认**：由需求部门签署，附报告 / 服务记录 / 进度证明之一；**未确认不得进入初审**。<br>5. 转入合同流程（见 UC-07）——★ **凡转账付款一律必须签合同**，原「无合同的小额对公直付」豁免已删除（批复 B3）。<br>6. 报综合运营主管初审 → 提交集团（见 UC-12）。<br>7. 集团流程完成 → 公户转账付款（**不可提前支出**）。 |
| **异常流 / 备选流** | A1. 交付物未确认 → 不进初审。<br>A2. 试图走「无合同的小额对公直付」→ 该豁免已删除，必须转入合同流程。<br>A3. 想提前支出 → 不允许；须待集团流程完成。 |

### UC-08　采购变更（档位就高）

| 项 | 内容 |
|---|---|
| **参与者** | 采购经办人（主）、主管领导、项目总经理、综合运营主管 |
| **前置条件** | 原合同已签署；合同签订后发生金额增加、工期顺延、范围调整、供应商变更、付款条件修改之一 |

| **后置条件** | 变更档位就高生效；变更链可回溯；关闭「化整为零」通道 |

| **后置条件** | 补办完成 → 紧急单核销闭合；未闭合单进入月度报送 |

| **主流程（正常）** | 1. 飞书推送事件。<br>2. 系统校验事件，计算幂等键（`instance_code` + `status`）。<br>3. 幂等键不存在 → 写一条「待处理」记录 → **立即返回**（3 秒窗口内必然返回）。<br>4. 异步侧拉取实例详情、解析表单字段、写入台账、更新状态。<br>5. 异步处理成功 → 记录完成。 |
| **主流程（对账补拉）** | 6. 每日定时执行：按 `approval_code` + 时间窗调用「批量取实例 ID」。<br>7. 与本地已入库集合**求差**。<br>8. 对缺失项「取实例详情」补录。<br>9. 记录对账结果（补录条数、缺失条数）。 |
| **异常流 / 备选流** | A1. **同一事件重复到达**（超时重推）→ 幂等键已存在 → 直接返回成功，**不重复写**。<br>A2. 异步处理失败 → 进入重试 / 死信队列，可人工重放；重试仍幂等。<br>A3. **本地数据被删除** → 下一次对账补拉全量恢复（把「事件丢失」从**故障**降为**延迟**）。<br>A4. 长连接断开 → 自动重连；重连期间的遗漏由对账补拉补齐。<br>A5. 事件端点耗时接近 3 秒 → 触发耗时告警（说明异步化被破坏）。 |
| **后置条件** | 事件不重复、不丢失（长期）；状态收敛；可自愈 |
| **关联需求** | FR-M3-01、FR-M3-02、FR-M3-03、FR-M3-04、FR-M3-06、FR-M3-07、FR-M0-02、FR-M0-07 |

### UC-17　启动自检与订阅告警（系统用例）

| 项 | 内容 |
|---|---|
| **参与者** | 自建系统（主）、系统管理员 |
| **前置条件** | 服务启动 |
| **主流程** | 1. 系统获取**单实例锁**；若已被占用（已有实例在跑）→ **拒绝启动并告警**。<br>2. 遍历 11 个 `approval_code`，**逐个调用「订阅审批事件」接口**。<br>3. 订阅结果落库。<br>4. 建立长连接并确认连通。<br>5. 检查数据库可写。<br>6. 自检四项（订阅状态 / 长连接状态 / 数据库可写 / 单实例）全部通过 → 正常提供服务，健康检查端点暴露四项状态。 |
| **异常流 / 备选流** | A1. **漏订阅**（未调用「订阅审批事件」）→ 自检报告失败项 + **告警**；★ 若不做自检，现象是「**静默无数据**」，极难排查。<br>A2. 订阅失败 → 重试；仍失败则告警并标记该模板不可用。<br>A3. 启动**第二个实例** → 被拒绝或告警（长连接在集群模式下不广播，多实例只有随机一个收到事件）。<br>A4. 数据库不可写 → 拒绝启动（避免半可用状态）。<br>A5. 运行期健康检查发现长连接断开 / 订阅失效 → 告警并尝试恢复。 |
| **后置条件** | 系统处于「可接收事件」的健康状态；不健康时明确告警而非静默 |
