# 采购与费用审批平台（自建侧）· 测试用例

> 结论先行：**测试的重心不在「审批功能」，而在「收事件这件事是否可靠」与「分权是否真的拦得住」。** 审批功能由飞书原生引擎承担（不在本系统测试范围）；本系统的可测风险集中在：幂等、先订阅、3 秒窗口、单实例、对账补拉、行·列权限、跨边界不受影响、档位判定。

| 范围 | 说明 |

| **纳入测试** | 事件接收与落库、幂等、订阅、单实例、对账补拉、状态机、台账写入与红标、看板指标、行·列权限、飞书免登、报送凭证包与「无凭证视为未提交」、审计留痕、备份恢复、降级演练、档位判定、编号规则 |

| **测试策略** | ① 高风险用例（TC-01～TC-15）必须全覆盖且优先执行；② 幂等与权限用例要求可重复执行；③ 降级与恢复演练须在独立环境做破坏性操作 |

## 4. 用例详述

### TC-01　同一 `approval_instance` 事件重复推送 3 次 → 只产生 1 条记录

| 项 | 内容 |
|---|---|
| **优先级** | P0 |
| **关联** | FR-M3-02 / UC-16 |
| **前置** | 服务运行中，长连接与订阅正常；数据库可写 |
| **步骤** | 1. 构造一条合法的 `approval_instance` 事件（`instance_code=X`，`status=APPROVED`）。<br>2. 向事件接入端点**连续推送 3 次完全相同的该事件**。<br>3. 查询业务表，统计 `instance_code=X` 且 `status=APPROVED` 的记录数。<br>4. 查询事件「待处理」表记录数。 |
| **预期结果** | 业务记录数 = **1**；第二次、第三次返回成功但**不新增记录**；「待处理」表不出现重复的业务记录；日志中可看到幂等命中记录。 |
| **备注** | ★ 这是必答题：官方允许事件未在 3 秒内处理完时**超时重推**，同一条事件可能到达多次。 |

### TC-02　未调用「订阅审批事件」→ 无事件、启动自检告警

| 项 | 内容 |
|---|---|
| **优先级** | P0 |
| **关联** | FR-M0-03、FR-M0-04 / UC-17 |
| **前置** | 11 个 `approval_code` 已知；可临时跳过订阅步骤 |
| **步骤** | 1. 在测试环境**移除 / 跳过**「订阅审批事件」调用（模拟漏实现）。<br>2. 启动服务。<br>3. 在飞书侧对某个模板发起一笔审批并使其状态变化。<br>4. 观察自建系统是否收到任何事件。<br>5. 查看启动自检报告与告警。 |
| **预期结果** | ① **一条事件都不会推送**（系统静默无数据）；② 启动自检报告**订阅项失败**并**触发告警**；③ 告警内容明确指出「未订阅 / 订阅失败」，可定位。 |
| **备注** | ★ **这是最易漏的一步**，且失败现象是「静默无数据」，若无自检则极难排查。 |

### TC-03　事件处理超过 3 秒 → 异步化后不因超时重推产生重复

| 项 | 内容 |
|---|---|
| **优先级** | P0 |
| **关联** | FR-M3-01、FR-M3-03 / UC-16 |
| **前置** | 服务运行中 |
| **步骤** | 1. 注入延迟：让**详情拉取 / 业务处理**步骤耗时 5 秒以上。<br>2. 推送 1 条事件。<br>3. 观察事件接入端点的响应耗时。<br>4. 模拟飞书侧因超时**重推同一事件** 2 次。<br>5. 统计业务记录数与事件处理耗时指标。 |
| **预期结果** | ① 事件接入端点**立即返回**（处理路径极短，远小于 3 秒）；② 详情拉取在异步侧完成，延迟不阻塞接入；③ 重推的 2 次命中幂等，**不产生重复记录**；④ 若接入端点耗时接近 3 秒，触发耗时告警（说明异步化被破坏）。 |
| **备注** | ★ 验证点是「异步化是否真的做到」，而非「处理得快」——慢可以，但接入必须快。 |

### TC-04　启动第二个实例 → 被拒绝或告警（单实例约束）

| 项 | 内容 |
|---|---|
| **优先级** | P0 |
| **关联** | FR-M8-01 / UC-17 |
| **前置** | 第一个实例已正常运行并持有单实例锁 |
| **步骤** | 1. 启动第二个服务实例。<br>2. 观察第二个实例的启动结果。<br>3. 观察日志与告警。 |
| **预期结果** | 第二个实例**被拒绝启动**（退出码非 0）或**明确告警**；第一个实例不受影响，继续正常接收事件。 |
| **备注** | ★ 长连接在集群模式下**不广播**——多实例只有一个随机实例收到事件，会造成「事件丢到未处理的实例」。必须禁止多副本。 |

### TC-05　删除本地数据后对账补拉 → 全量恢复

| 项 | 内容 |
|---|---|
| **优先级** | P0 |
| **关联** | FR-M0-07 / UC-16 |
| **前置** | 已有不少于 20 笔已完成审批的历史数据（覆盖多张单据、多档位）；对账任务可手动触发 |
| **步骤** | 1. 记录当前业务数据条数与关键状态。<br>2. **删除本地全部业务数据**（保留配置与订阅状态）。<br>3. 手动触发「对账补拉」（批量取实例 ID → 求差 → 取实例详情补录）。<br>4. 比对恢复后的数据与删除前。 |
| **预期结果** | 恢复条数与删除前**一致**；关键状态、金额、单据类型正确；对账报告列出「缺失条数 / 补录条数」。 |
| **备注** | ★ 这一机制把「事件丢失」从**故障**降为**延迟**。有了它，事件可靠性要求可从「不能丢」放宽到「不能长期丢」。 |

### TC-06　越权访问台账行级 → 被拦截

| 项 | 内容 |
|---|---|
| **优先级** | P0 |
| **关联** | FR-M5-02 / UC-13 |
| **前置** | 已构造两个部门的申请人（A 部门、B 部门）各若干条记录；已构造一个只能看本部门的主管领导账号 |
| **步骤** | 1. 以 A 部门主管领导登录。<br>2. 请求台账列表（`GET /api/ledger/{table}`）。<br>3. 尝试直接按 B 部门记录的 ID 请求单条（`GET /api/ledger/{table}/{id}`）。<br>4. 检查返回内容与审计日志。 |
| **预期结果** | 列表**只返回 A 部门记录**；直接按 ID 请求 B 部门记录**被拒绝**（无权限，不返回数据）；越权请求**留痕**。 |
| **备注** | ★ 行级权限是本系统唯一不可替代的价值，必须逐角色验证。 |

### TC-07　越权访问台账列级 → 被拦截

| 项 | 内容 |
|---|---|
| **优先级** | P0 |
| **关联** | FR-M5-03 / UC-13 |
| **前置** | 已定义列级可见性（如「金额列仅项目总经理 / 综合运营主管可见」） |
| **步骤** | 1. 以**采购经办人**（不具金额列权限）登录。<br>2. 请求台账列表。<br>3. 检查返回 JSON 中是否包含金额字段。<br>4. 尝试通过查询参数 / 导出接口绕过列过滤。<br>5. 以项目总经理登录重复步骤 2，检查金额列是否可见。 |
| **预期结果** | 采购经办人返回结果**不含金额字段**（连字段名都不出现在响应中）；绕过尝试被拒绝；项目总经理可见金额列。 |
| **备注** | ★ 列级权限须在**服务端**做，不能只在前端隐藏列（前端隐藏可被绕过）。 |

### TC-08　断网 / 自建系统停机 → 飞书侧审批不受影响
