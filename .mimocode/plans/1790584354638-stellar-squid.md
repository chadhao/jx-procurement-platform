# 项目学习笔记：jx-procurement-platform

> 本文件为项目结构学习成果，作为后续任何任务的背景基线。原任务仅要求"学习项目结构"，暂无实现计划。

## 一、项目定位

湖南江熙新材料（岳阳煅后石油焦磨粉项目，约 20–50 人）的**采购与费用审批平台**。飞书只承担"展示/待办/通知 + 同意·拒绝"，表单、流转、分档、编号、台账全部在我方系统实现（"架构转向 ③"：三方审批定义走 API 建立，`POST /open-apis/approval/v4/external_approvals`）。

## 二、技术栈与架构

- **后端**：Go 1.24 + Echo v4 + modernc.org/sqlite（WAL）+ 飞书 larksuite/oapi-sdk-go（长连接回调 + 三方审批 API）
- **前端**：Vue3 + Vite + vue-router + ECharts，`go:embed` 内嵌为单二进制 `bin/jxapproval`
- **部署**：单实例（internal/singlelock）+ systemd；S3 兼容对象存储（自实现 SigV4）
- **硬约束**：单实例、事件幂等、回调"落盘即 200"

## 五、业务交付文档（WorkBuddy\江熙新材\deliverables\procurement-approval）

**现行有效四件套**（旧版均已标废留档）：

2. `审批流程图集V3.0.html` — 10 张流程图 + 25 条批复台账
3. `采购与费用审批体系配置工具表_v3.0.xlsx` — 14 张工作表
4. `三方审批定义建立指引V1.0.html` — API 建定义路线（对应代码 tag 0.3.3-s3）

**业务核心规则**：
- 三条组织边界：不设集团审批节点（止于"归口提交集团"）、不设财务岗（集团统一处理，本地仅 <1,000 备付金）、不设采购岗（经办人由主管领导审批时当场指定）
- 采购三档：<1,000 / 1,000–5,000 / >5,000（1,000 是签合同、走公户、两级审批的总闸）；费用不分档、一律事前申请
- 23 个一级分类（P01–P08 / S01–S07 / M01–M08）是流程分流起点
- 11 张单据（BA/PR/SA/RFQ/BJ/SS/CT/PC/GR/QC/SUB），编号 `前缀-YYMM-####` 一单到底；12 台账 + 4 看板
- 三条例外：独家、紧急（先支出+24h 补录）、变更（档位就高）；驳回 = 退回修改重提、原单留痕
- 不设数值限额，管控靠审批链 + 必备附件 + 单列统计 + 后置审计

**待办/待确认**：10 项待确认（含第 25 项行·列权限 → 决定飞书免费版 vs 商业版）、S-1（L03 台账生产者）须在导入配置前拍板、合同范本与集团启动条件待集团确认。
